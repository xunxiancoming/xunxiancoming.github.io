原理：这条链路到底在做什么

WHY

大模型不能直接「读懂」文字，它只认识数字。所以要把语料变成向量（embedding）， 让语义相近的句子在数学空间里彼此靠近；再把向量交给向量数据库存起来 —— 这就是「持久化」三个字的含义：写一次，处处查，进程没了数据还在。

PRINCIPLE 01

Embedding：文本 → 768 维浮点数组

本案例用 Ollama 本地运行的 embeddinggemma 模型，每段文字输出 768 个浮点数。两段文字的向量方向越接近，余弦相似度越接近 1。 下文 Step 1 会用真实数据验证：语义相近的「我喜欢吃苹果 / 苹果是我喜欢的水果」得分 0.9259，而语义转向电子产品的「我喜欢苹果手机」只得到 0.7834。

PRINCIPLE 02

持久化：为什么不能只用内存向量库

InMemoryVectorStore 随进程退出而蒸发，每次启动都要重新嵌入全部语料； 也无法被多个服务共享。向量库把「嵌入计算」与「向量存储」解耦：Redis Stack 用 RediSearch 模块在服务端建索引、答 KNN 查询；Milvus Lite 则把数据写进 本地数据目录。两者都让向量具备重启不丢、跨进程共享的能力。

02

Step 1 · 把文字变成 768 维向量

EMBED
PRINCIPLE

两个方法，两种用途

embed_query(问题) —— 查询时用，把用户提问变成向量； embed_documents([文本…]) —— 入库时用，批量把语料变成向量。 两者底层调用 Ollama 的同一个 /api/embed 接口， 产出的向量处于同一空间，因此可以直接比对。注意：向量维度由模型决定， 它必须与向量库索引声明的维度一致，换模型就要重建索引（见坑 #1）。

01_embeddings_basics.pyPYTHON
"""Step 1：认识 OllamaEmbeddings —— 文本如何变成 768 维向量。"""

import numpy as np

from common import EMBED_MODEL, banner, get_embeddings

banner(f"Step 1  OllamaEmbeddings 基础（模型: {EMBED_MODEL}）")

embeddings = get_embeddings()

text = "LangChain 是一个用于构建上下文感知推理应用的框架"
vector = embeddings.embed_query(text)
print(f"\n[1] embed_query 单条文本")
print(f"    文本: {text}")
print(f"    向量维度: {len(vector)}")
print(f"    前 8 维: {[round(v, 4) for v in vector[:8]]}")

texts = ["我喜欢吃苹果", "苹果是我喜欢的水果", "我喜欢苹果手机"]
doc_vectors = embeddings.embed_documents(texts)
print(f"\n[2] embed_documents 批量文本")
print(f"    返回向量条数: {len(doc_vectors)}，每条维度: {len(doc_vectors[0])}")


def cosine_similarity(a, b) -> float:
    return float(np.dot(a, b) / (np.linalg.norm(a) * np.linalg.norm(b)))


print("\n[3] 两两余弦相似度（越接近 1 越相似）")
for i in range(len(texts)):
    for j in range(i + 1, len(texts)):
        score = cosine_similarity(doc_vectors[i], doc_vectors[j])
        print(f"    文本{i + 1} vs 文本{j + 1}: {score:.4f}   "
              f"「{texts[i]}」 ↔ 「{texts[j]}」")

Step 2 · 切分：检索单位是 chunk 不是整篇

SPLIT
PRINCIPLE

chunk_size 与 chunk_overlap

整篇文章嵌入成一个向量会把主题稀释掉；切成太碎又会拦腰截断语义。 RecursiveCharacterTextSplitter 按分隔符优先级 （\n\n → \n → 。 → ，）递归切分： chunk_size=200 限制单块长度， chunk_overlap=40 让相邻块首尾重叠，保证跨边界的关键信息不丢。

02_text_split.pyPYTHON
"""Step 2：文档切分 —— 长文章如何变成适合入库的 chunk。"""

from langchain_text_splitters import RecursiveCharacterTextSplitter

from common import LONG_ARTICLE, banner

print(f"\n[1] 原始文章长度: {len(LONG_ARTICLE)} 字符")

splitter = RecursiveCharacterTextSplitter(
    chunk_size=200,
    chunk_overlap=40,
    separators=["\n\n", "\n", "。", "，", ""],

chunks = splitter.split_text(LONG_ARTICLE)

print()
for i, chunk in enumerate(chunks):
    preview = chunk.replace("\n", "⏎")
    print(f"    #{i + 1:>2}  长度={len(chunk):>3}  {preview[:52]}...")

Step 3 · 写入 Redis Stack 并检索

CORE
PRINCIPLE

RedisConfig 的五个关键参数

index_name 索引名（服务端 FT._LIST 可见）； distance_metric="COSINE" 用余弦距离； indexing_algorithm="FLAT" 精确暴力搜索，结果与逐对计算完全一致，适合万条以内数据； embedding_dimensions=768 必须等于模型实际输出维度； metadata_schema 把 source/category 声明为 tag 字段， 才能在检索时做 预过滤（先缩小候选集，再做 KNN）。

03_redis_store.pyPYTHON
"""Step 3：把向量写入 Redis Stack 并做相似度检索（含元数据过滤）。"""

from langchain_redis import RedisConfig, RedisVectorStore
from redisvl.query.filter import Tag

from common import (
    EMBED_MODEL,
    INDEX_NAME,
    REDIS_URL,
    banner,
    build_documents,
    get_embeddings,
    reset_redis_index,
)

banner("Step 3  RedisVectorStore 写入与检索")

removed = reset_redis_index(INDEX_NAME)
print(f"\n[0] 清理旧索引 {INDEX_NAME}: {'已删除' if removed else '首次创建'}")

config = RedisConfig(
    index_name=INDEX_NAME,
    redis_url=REDIS_URL,
    distance_metric="COSINE",
    indexing_algorithm="FLAT",
    embedding_dimensions=768,
    metadata_schema=[{"name": "source", "type": "tag"}, {"name": "category", "type": "tag"}],
)
store = RedisVectorStore(embeddings=get_embeddings(), config=config)

docs = build_documents()
keys = store.add_documents(docs)
print(f"[1] 写入 {len(docs)} 条文档，索引: {INDEX_NAME}，key 前缀: {store.key_prefix}")
print(f"    返回 keys 示例: {keys[:2]}")

query = "怎么在本地跑一个嵌入模型？"
print(f"\n[2] 相似度检索: 「{query}」 (k=3, COSINE 距离越小越相似)")
for doc, score in store.similarity_search_with_score(query, k=3):
    print(f"    距离={score:.4f}  相似度≈{1 - score:.4f}  "
          f"[{doc.metadata['category']}] {doc.page_content}")

print(f"\n[3] 元数据过滤: 只在 category='向量数据库' 中检索")
filt = Tag("category") == "向量数据库"
for doc, score in store.similarity_search_with_score(query, k=3, filter=filt):
    print(f"    距离={score:.4f}  [{doc.metadata['category']}] {doc.page_content}")

print(f"\n[4] 索引里现在有哪些? (redis FT._LIST)")
from common import get_redis_client

client = get_redis_client()
print(f"    {client.execute_command('FT._LIST')}")
info = client.ft(INDEX_NAME).info()
stats = {k: info[k] for k in info if "doc" in k.lower() or "num" in k.lower()}
print(f"    FT.INFO 关键统计: {stats}")

Step 4 · 持久化证明：只连不写，照样查得到

PROOF
PRINCIPLE

from_existing=True 是关键开关

新建索引时库会执行 FT.CREATE；而 from_existing=True 表示「索引已存在，直接挂载」， 绝不写入任何数据。因此只要这个只读进程还能检索到内容， 数据就必然来自 Redis 服务端的落盘存储，而非内存残留。本步给出三重证据： 新进程检索、服务端 FT.INFO 统计、以及再开一个子解释器独立查询。

04_persistence_check.pyPYTHON
"""Step 4：持久化验证 —— 全新进程只连不写，依然能检索到数据。"""

import subprocess
import sys

from langchain_redis import RedisConfig, RedisVectorStore

from common import (
    INDEX_NAME,
    REDIS_URL,
    banner,
    get_embeddings,
    get_redis_client,
)

banner("Step 4  持久化验证（新进程只读，不写入任何数据）")

config = RedisConfig(
    index_name=INDEX_NAME,
    redis_url=REDIS_URL,
    from_existing=True,
    distance_metric="COSINE",
    indexing_algorithm="FLAT",
    embedding_dimensions=768,
)
store = RedisVectorStore(embeddings=get_embeddings(), config=config)
print(f"\n[1] 以 from_existing=True 打开已存在的索引: {INDEX_NAME}")
print(f"    本进程没有调用 add_documents，数据只能来自 Redis 落盘")

query = "向量数据重启后还在吗？"
print(f"\n[2] 新进程直接检索: 「{query}」")
for doc, score in store.similarity_search_with_score(query, k=2):
    print(f"    距离={score:.4f}  {doc.page_content}")

client = get_redis_client()
info = client.ft(INDEX_NAME).info()
print(f"\n[3] Redis 服务端索引统计（证明数据在服务端持久保存）")
for key in ["index_name", "num_docs", "num_records", "hash_indexing_failures"]:
    if key in info:
        print(f"    {key}: {info[key]}")

print(f"\n[4] 对比重实验：另一个解释器进程独立执行一次检索")
code = (
    "from langchain_redis import RedisConfig, RedisVectorStore;\n"
    "from common import get_embeddings, INDEX_NAME, REDIS_URL;\n"
    "cfg = RedisConfig(index_name=INDEX_NAME, redis_url=REDIS_URL, from_existing=True,"
    " embedding_dimensions=768);\n"
    "s = RedisVectorStore(embeddings=get_embeddings(), config=cfg);\n"
    "d, sc = s.similarity_search_with_score('Redis 怎么做向量检索', k=1)[0];\n"
    "print('    [子进程] top1 距离=%.4f  %s' % (sc, d.page_content))"
)
result = subprocess.run(
    [sys.executable, "-c", code],
    capture_output=True,
    text=True,
    cwd=str(__import__("common").PROJECT_ROOT / "rag_ollama_persistence"),
)
print(result.stdout.strip() or result.stderr.strip())

Step 5 · 完整 RAG 链：检索 + 生成

RAG
PRINCIPLE

用 LCEL 把两条支线合成一条管道

retriever | format_docs 是检索支线： 取 top-3 片段并拼成上下文字符串；lambda x: x 是 透传支线：把原问题原样送进提示词。两者在字典 {"context": …, "question": …} 中并行执行， 再依次流经 Prompt → ChatOllama(llama3.2) → StrOutputParser。提示词里写死「仅根据参考资料回答」， 是抑制幻觉最简单有效的手段。

05_rag_chain.pyPYTHON
"""Step 5：完整 RAG 链 —— 检索 Redis Stack + Ollama 大模型生成回答。"""

from langchain_core.output_parsers import StrOutputParser
from langchain_core.prompts import ChatPromptTemplate
from langchain_redis import RedisConfig, RedisVectorStore

from common import (
    CHAT_MODEL,
    INDEX_NAME,
    REDIS_URL,
    banner,
    get_chat_model,
    get_embeddings,
)

banner("Step 5  RAG 链：Redis 检索 + Ollama 生成")

config = RedisConfig(
    index_name=INDEX_NAME,
    redis_url=REDIS_URL,
    from_existing=True,
    distance_metric="COSINE",
    indexing_algorithm="FLAT",
    embedding_dimensions=768,
)
store = RedisVectorStore(embeddings=get_embeddings(), config=config)
retriever = store.as_retriever(search_kwargs={"k": 3})


def format_docs(docs) -> str:
    return "\n\n".join(
        f"[{d.metadata.get('category', '-')}] {d.page_content}" for d in docs
    )


prompt = ChatPromptTemplate.from_template(
    "你是 RAG 助手。请仅根据下方参考资料回答问题，"
    "若资料中没有答案就直说不知道。\n\n"
    "参考资料：\n{context}\n\n问题：{question}"
)

chain = (
    {"context": retriever | format_docs, "question": lambda x: x}
    | prompt
    | get_chat_model()
    | StrOutputParser()
)

for question in [
    "Redis 是怎么做向量检索的？",
    "本地跑嵌入模型应该用什么工具？",
]:
    print(f"\n[问题] {question}")
    docs = retriever.invoke(question)
    print("[检索到的 top-3 片段]")
    for i, d in enumerate(docs, 1):
        print(f"    {i}. [{d.metadata.get('category')}] {d.page_content}")
    print(f"[生成模型] {CHAT_MODEL}")
    print("[回答]")
    answer = chain.invoke(question)
    for line in answer.splitlines():
        print(f"    {line}")

Step 6 · Milvus Lite 对照方案

COMPARE
PRINCIPLE · 关键差异

得分方向正好相反

同一份语料、同一个查询、同一个模型，两个库给出的数值互为镜像： Redis similarity_search_with_score 返回 COSINE 距离（越小越相似）， top1 为 0.4695；Milvus 在 metric_type="COSINE" 下返回 相似度（越大越相似），同一条文档得 0.5305 —— 两者相加恰好为 1。做跨库结果融合或调阈值时，这个方向差异必须先统一。

另外，Milvus 用 enable_dynamic_field=True 后元数据成为动态字段， 过滤表达式写成 expr='category == "向量数据库"'； Redis 则用 redisvl 的 Tag("category") == "…" 对象。语法不同，语义等价。

09

常见坑：踩过的都写在这

PITFALLS
1
维度必须与索引声明一致

embedding_dimensions=768 是写死给索引看的。换成 nomic-embed-text（768）之外的模型（如 1024 维模型）后，旧索引会直接报维度不匹配 —— 正确做法是先 drop index 再重建，本教程的 reset_redis_index() 就是为此准备的。

2
必须用 redis/redis-stack 镜像

普通 redis:7 镜像没有 RediSearch 模块，建索引时报 unknown command 'FT.CREATE'。启动后用 MODULE LIST 确认存在 search。

3
langchain-redis 不支持 Python 3.14

其 requires_python = <3.14,>=3.10。本项目 requirements.txt 也注明需 3.10–3.13，故使用 conda zeroai（3.10.21）环境运行。

4
废弃 API：langchain_community.vectorstores.Redis

旧写法 from langchain_community.vectorstores import Redis 已标记 deprecated（自 0.3.13 起），替代品是 langchain_redis.RedisVectorStore + RedisConfig，本教程全部采用新 API。

5
得分方向相反导致阈值判断出错

把 Redis 的距离当相似度用（或反之）会让「过滤低分结果」变成「过滤高分结果」。统一做法：先转换成同向（例如全部转成 1 − 距离）再比较。

6
重复运行导致数据翻倍

add_documents 是追加语义。脚本若不清理，第二次运行会写入 32 条并污染检索结果。开头先 drop 索引（Step 3 已内置），或改用幂等的 id。

7
Milvus Lite 的 uri 是目录不是文件

3.x 版本创建的 milvus_rag_demo.db 实际是一个含 collections/、LOCK 的目录，清理时要用 shutil.rmtree() 而非 unlink()。
